# Голосовой инбокс

> [!info] Статус
> **Область:** inbox · **Статус:** код готов · **Деплой:** нет · **Миграция:** `0008` применена в прод 17.09

## Суть
Кнопка 🎤 в `QuickCapture` на `/inbox`: распознавание речи браузером через Web Speech API, текст падает в то же поле ввода, отправка — обычной кнопкой «Записать». Запись помечается `source='voice'`. Ярлык PWA «Записать мысль» (`shortcuts` в манифесте) ведёт на `/inbox?rec=1` и поднимает микрофон сразу.

## Зачем
Мысль приходит на ходу, набивать её руками некогда. Всё, что нужно, — надиктовать и забыть; разбор потом, обычным путём через `→ в задачу`.

## Решения
- **Web Speech API, а не внешний STT.** В Chrome на Android распознаёт Google: бесплатно, без ключей и без ещё одного сервиса в хозяйстве. Safari на iOS API не поддерживает — кнопка скрыта через `supported`, остальной инбокс работает как раньше.
- **Склейка через `joinTranscript()`, а не конкатенация.** Движок держит в `results` нарастающие версии одной фразы («Не» → «Не забудьте» → «Не забудьте взять») и метит `isFinal` каждую. Функция отличает версию от нового куска по вхождению: более полная версия побеждает, новый кусок дописывается через пробел. Через неё идут сборка `results`, склейка с прошлыми сессиями и подстановка к напечатанному руками. Без неё фраза разрасталась в 12 раз ([[ERRORS]], 18.09).
- **Состояние, а не события.** `collectTranscript()` читает `results` с нулевого индекса и отдаёт текст целиком; подписчик заменяет значение. Текст завершённых сессий копится в `committedRef` — при перезапуске `results` обнуляется.
- **Отправка руками, не автоматом по тишине.** Распознавание врёт, и молчаливая отправка мусора в инбокс хуже лишнего нажатия. Текст сначала виден в поле.
- **Перезапуск сессии в `onend`.** На Android движок закрывает сессию после паузы в речи. `wantListeningRef` отличает нашу остановку по кнопке от самопроизвольной; если `start()` бросает — считаем диктовку оконченной, иначе получится цикл перезапусков.
- **`no-speech` и `aborted` не показываем.** Это рабочий шум движка (пауза в речи, наша же остановка), а не поломка.
- **`supported` через `useSyncExternalStore`.** `useState` + `useEffect` разошёлся бы с SSR-разметкой при гидрации, и линтер правила react-hooks это ловит.
- **Автостарт по `?rec=1` — вежливый.** Chrome вправе потребовать жест пользователя; если не сработает, просто останется кнопка. На это ничего не завязано.

## Чего тут нет
Офлайна. Web Speech API гоняет звук на серверы браузера — без сети диктовка не работает, и вся запись мыслей «в метро» остаётся непокрытой.

## Отвергнутые варианты
- **VK-бот с расшифровкой на стороне VK.** Проверено на живом сообществе «Инбокс» (id 241565122) 17.09: в `audio_message` приходят только `access_key`, `duration`, `id`, `link_mp3`, `link_ogg`, `owner_id`, `waveform`. Полей `transcript` / `transcript_state` нет ни на `v=5.199`, ни на `v=5.131`, ни в `getHistory`, ни в `getById`. Бесплатной расшифровки у VK для ботов нет — нужен внешний STT.
- **Бот в MAX.** В документации (`dev.max.ru`) слов «транскрипция», «расшифровка», `voice`, `speech` нет вовсе; голосовые как отдельный тип вложения не описаны. STT всё равно свой, а сверху — обязательный профиль юрлица/ИП/самозанятого, модерация бота, сертификат Минцифры для запросов к API и заметная текучка методов.
- Оба пути остаются открытыми: `inbox_item.source` и `vk_message_id` под них уже есть, вебхуку останется писать в готовую таблицу.

## Проверка
`npm run check:speech` — 8 проверок на потоках, снятых с реальных записей: нарастающие версии схлопываются, разные куски речи складываются, регистр не мешает узнать ту же фразу, перезапуск сессии не удваивает текст, промежуточный результат не течёт в финальный. Тестового фреймворка в проекте нет, поэтому это самостоятельный скрипт рядом с `planer.ts` и `vapid.ts`.
