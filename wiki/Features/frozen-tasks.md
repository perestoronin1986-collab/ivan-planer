# Заморозка задач

> [!info] Статус
> **Область:** tasks · **Статус:** код готов · **Деплой:** нет · **Миграция:** `0007` вручную в Supabase SQL Editor

## Суть
`task.frozen_at` (timestamptz, null = не заморожена) + Dexie v5. Задача с `frozen_at` уходит из «⚠ Просрочено» и «⚡ Активные» на `/today` во вкладку «❄ Заморожено». `due_at` не трогаем — разморозка возвращает задачу ровно туда, где она была.

## Зачем
«Просрочено» копило дела, которые сейчас не актуальны, но выбросить жалко. Список переставал читаться, и настоящая просрочка тонула в шуме. Правило: заморозка — это не перенос срока, а признание «сейчас не делаю». Выполнить замороженную можно прямо во вкладке — галочка работает как обычно, задача уходит в `/done`.

## Решения
- **Флаг, а не дата разморозки.** Автовозврат в «Просрочено» вернул бы ровно ту проблему, ради которой фича делалась. Возврат только руками, кнопкой ↩.
- **`processOverdueTasks` пропускает замороженные** (`.is("frozen_at", null)`) — иначе задача с `overdue_action='autocomplete'` закрылась бы сама, пока лежит в заморозке.
- **Dexie не индексирует `null`**, поэтому вкладка читается как `where("frozen_at").above("")` — в индексе лежат только замороженные, фильтровать всю таблицу не нужно. Апгрейд v5 добивает `frozen_at = null` в старые строки, иначе `undefined` тоже выпал бы из индексов.
- **Другие экраны не трогали.** В `/week`, `/month`, `/tasks`, `/search` замороженная задача видна как обычно — её прячут только списки «что делать сегодня».

## Попутный фикс
В `upsert_task_if_newer` в `DO UPDATE SET` не было `priority` (колонка появилась в `0004`, RPC не обновили). Правка приоритета существующей задачи через офлайн-синк молча терялась. Добавлено вместе с `frozen_at`.
