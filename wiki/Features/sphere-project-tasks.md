# Раскрытие задач проекта в сфере

> [!info] Статус
> **Область:** spheres · **Статус:** in-progress (код готов, ждёт визуального чека + деплоя) · **Деплой (Vercel):** нет · **Миграция:** —

## Суть
В `/spheres/[sphereId]` клик по проекту раскрывает его незаконченные задачи на месте. Раньше строка вела на страницу проекта: чтобы понять, что в проекте висит, приходилось уходить со сферы и возвращаться — по проекту на заход. Счётчик незаконченных в строке отвечает на тот же вопрос вообще без клика.

Переход на страницу проекта не выкинут, а перенесён внутрь раскрытого блока («→ открыть проект»): там остались выполненные задачи, форма создания и удаление. Раскрытие — это быстрый просмотр, страница — работа с проектом.

## Реализация
- **UI:** `SphereProjectsList` (клиентский) в `app/spheres/[sphereId]/`.
- **Данные:** проекты — пропсом из серверного компонента (Supabase), задачи — из Dexie через `useLiveQuery`. Та же связка, что у соседнего `SphereTasksList`, поэтому раскрытие работает офлайн.
- **Server actions / таблицы:** не трогали, миграции нет.

> [!warning] Имя не `ProjectsList`
> Так уже зовётся компонент `/projects`. Тот экран другой — всё всегда развёрнуто, есть смена сферы и toggle done, — переиспользовать не вышло. Имя `SphereProjectsList` держит пару с `SphereTasksList` в той же папке.

## Решения
- **Раскрытых проектов может быть несколько.** Аккордеон «только один открыт» прячет то, что пользователь только что смотрел.
- **Состояние раскрытия не персистится** — по просьбе пользователя, при заходе всё свёрнуто. Отличается от `/projects`, где `hiddenDone` лежит в localStorage. Если попросят память — ключ на сферу, localStorage, не БД (должно работать офлайн).
- **Иконка проекта.** Форма создания проекта собирала `icon`, а старая строка его не рендерила — поле молча терялось. Строка всё равно переписывалась, добавили.
