# Уроки и допущенные ошибки

> [!abstract] Цель
> Фиксировать факапы и грабли, чтобы не повторять. Каждый блок — симптом, причина, фикс, урок.

## БД / данные

> [!bug] 2026-05-16 — Прямой TCP к Supabase Postgres заблокирован
> **Симптом:** Drizzle через `postgres` (`5432`/`6543`) не подключается, таймауты.
> **Причина:** Сеть/провайдер блокирует прямой TCP к Supabase.
> **Фикс:** Слой данных на PostgREST через `@supabase/supabase-js`. Drizzle runtime удалён, `schema.ts` — только для миграций.
>
> > [!tip] Урок
> > Перед выбором драйвера БД — проверить доступность TCP-портов из dev. Для Supabase под Win/Россия — сразу PostgREST.

> [!bug] 2026-05-18 — datetime-local input → не ISO
> **Симптом:** `due_at` сохранялся со сдвигом TZ.
> **Причина:** `<input type="datetime-local">` возвращает локальную строку без TZ.
> **Фикс:** Хелпер `toIso()` в `spheres/actions.ts`.
>
> > [!tip] Урок
> > Никогда не отдавать `datetime-local` напрямую в БД. Всегда через конвертер.

> [!bug] 2026-05-19 — Сравнение дат строкой ломалось
> **Симптом:** `task.due_at < today` неверно для свежих задач.
> **Причина:** Supabase `+00:00` vs JS `.000Z` — лексикографическое сравнение не работает.
> **Фикс:** Только `new Date(x).getTime()`.
>
> > [!tip] Урок
> > Даты — только через `.getTime()`. Никаких `>` `<` на строках ISO.

## Server actions / логика

> [!bug] 2026-05-18 — revalidatePath отсутствовал у toggleTask/deleteTask
> **Симптом:** После клика чекбокса задача не обновлялась до ручного refresh.
> **Причина:** Action менял БД, но не инвалидировал кэш страницы.
> **Фикс:** `revalidatePath("/today")` в каждом мутирующем action.
>
> > [!tip] Урок
> > Любой мутирующий server action → `revalidatePath` для всех затронутых маршрутов. Чек-лист.

> [!bug] 2026-05-19 — Reschedule просрочки сдвигал due_at на now+24h
> **Симптом:** Задача с просрочкой улетала на завтра.
> **Причина:** `dueAt = now + 24h`.
> **Фикс:** `reschedule` оставляет в overdue-секции, инкрементирует `carry_count` (22cb0b7).
>
> > [!tip] Урок
> > Overdue: не «перенести на потом», а «оставить видимой сейчас + посчитать перенос».

> [!bug] 2026-05-19 — createRecurringTask мог создать >500 вхождений
> **Симптом:** Зависание на rrule с большим диапазоном.
> **Причина:** Нет лимита occurrences.
> **Фикс:** Кап 500, Zod-валидация, rollback шаблона при ошибке.
>
> > [!tip] Урок
> > Операция, генерящая массив из пользовательского ввода — лимит сверху обязателен.

## Offline / PWA / sync

> [!bug] 2026-05-21 — Dexie .where("processed_at").equals(null) падал
> **Симптом:** Inbox не загружался офлайн.
> **Причина:** IndexedDB не индексирует `null` как ключ.
> **Фикс:** `toArray().filter(x => x.processed_at == null)`.
>
> > [!tip] Урок
> > Dexie/IndexedDB — фильтр по `null` всегда через `.filter()`, не индекс.

> [!bug] 2026-05-21 — PWA manifest и /offline требовали авторизацию
> **Симптом:** Установка PWA падала с 401 на manifest.
> **Причина:** Middleware редиректил на `/login` все маршруты включая `/manifest.webmanifest`, `/offline`, `/icon*`.
> **Фикс:** Расширить `PUBLIC_PATHS`.
>
> > [!tip] Урок
> > При добавлении PWA-эндпоинтов — сразу в публичный whitelist.

> [!bug] 2026-05-21 — Outbox poison entry блокировал sync
> **Симптом:** Один битый item → весь sync встаёт.
> **Причина:** FIFO останавливался на ошибке, attempts++ без лимита.
> **Фикс:** Dead-letter outbox: после N попыток entry = failed, sync идёт дальше.
>
> > [!tip] Урок
> > FIFO-очереди — всегда dead-letter после M попыток, иначе одно битое сообщение парализует пайплайн.

> [!bug] 2026-05-22 — Service Worker не обновлял shell при выкатке
> **Симптом:** Старые клиенты после деплоя видели stale UI.
> **Причина:** Версия кэша SW не менялась → install-skip.
> **Фикс:** Bump `VERSION` в `public/sw.js` при изменении shell.
>
> > [!tip] Урок
> > Любая правка `sw.js`/precache → инкремент `VERSION`. Иначе кэш залипает.

> [!bug] 2026-05-22 — Middleware падал при сетевой ошибке Supabase
> **Симптом:** При обрыве сети — выкидывало на `/login`.
> **Причина:** `getSession()` кидал → fail-closed.
> **Фикс:** try/catch — на сетевую ошибку оставлять сессию из cookie (fail-open).
>
> > [!tip] Урок
> > Auth-middleware в PWA — fail-open при сетевых ошибках, fail-closed только при доказанной невалидности токена.

## Инфраструктура / крон

> [!bug] 2026-08-07 — GitHub Actions `*/5` на деле гонял раз в час
> **Симптом:** Письмо «cron-push: All jobs were cancelled», аннотация `The job was not acquired by Runner of type hosted even after multiple attempts` (два запуска подряд 06.08, job висел в очереди 15 и 18 минут и не получил раннер).
> **Причина:** Само письмо — транзиент, нехватка GitHub-hosted раннеров. Но проверка истории вскрыла настоящее: при `*/5 * * * *` за 831 запуск фактическая частота была ~1 раз в час, разрывы до 3 часов. GitHub деприоритизирует частые schedule-триггеры и просто выбрасывает запуски.
> **Фикс:** Основной крон — внешний сервис (cron-job.org, 5 мин, `Authorization: Bearer <CRON_SECRET>`). GitHub Actions понижен до `23 * * * *` и оставлен резервом.
>
> > [!tip] Урок
> > `schedule` в GitHub Actions — не крон, а пожелание: чем чаще просишь, тем больше выбрасывается. Всё, что должно срабатывать чаще раза в час, — наружу. И проверять не «зелёный ли последний запуск», а фактические интервалы: `/actions/workflows/<file>/runs` + разница `created_at` соседних. Здесь всё было зелёное 829 раз подряд и при этом не работало как задумано.
> > Минута на раннере считается целиком, так что `*/5` на приватном репо ещё и съел бы бесплатный лимит за неделю. Здесь спасло, что репо публичный.

## Безопасность / окружение

> [!danger] 2026-06-11 — Пароль Postgres в публичном репо
> **Симптом:** `scripts/test-db.ts` с захардкоженным паролём БД, файл в git, репо публичный.
> **Причина:** Диагностический скрипт закоммитили с секретом.
> **Фикс:** Файл удалён, пароль сброшен (Supabase → Settings → Database → Reset password). Закрыто — подтверждено 2026-07-15.
>
> > [!tip] Урок
> > Секреты только в `.env.local`. Одноразовый скрипт с кредами — в `.gitignore` или сразу удалять.

> [!danger] 2026-07-15 — Тот же пароль лежал в `п.txt` с первого коммита
> **Симптом:** Скретч-файл `п.txt` в корне с паролём БД и именем Vercel-организации — отслеживался git, в HEAD, репо публичный. Пролежал с `8d7c235` (20.05) незамеченным два месяца.
> **Причина:** Личную заметку с кредами положили в папку проекта, а не вне репо. При аудите июня нашли `test-db.ts`, но не её.
> **Фикс:** `git rm --cached п.txt` + `.gitignore`. Историю не переписывали: пароль из этого файла — досбросовый (ротация 11.06 была позже), строка мертва, force-push публичного репо ради неё не оправдан.
>
> > [!tip] Урок
> > Файл нашёлся только когда его прочитали, а не сгрепали: `git ls-files` отдаёт не-ASCII имена в escape-виде (`\320\277.txt`), поэтому `grep "п.txt"` молча не матчится. Для аудита секретов — `git -c core.quotepath=false ls-files`, и не полагаться на `git status` (незмененный файл в нём не виден).
> > Ротация закрывает инцидент надёжнее чистки истории: секрет в публичном репо считать скомпрометированным с момента пуша, форки и кэши GitHub всё равно не вычистить.

> [!bug] 2026-06-11 — Magic link в dev уводит на прод
> **Симптом:** Логин с localhost: `redirect_to` = прод, локальная сессия не создаётся.
> **Причина:** `http://localhost:3000/**` нет в Supabase Auth → Redirect URLs. Supabase молча заменяет недопустимый redirect на Site URL.
> **Фикс:** Добавить `http://localhost:3000/**` в allowlist (Dashboard).
>
> > [!tip] Урок
> > Недопустимый `emailRedirectTo` Supabase не отклоняет с ошибкой, а тихо подменяет — проверять allowlist при новых окружениях.

## Технический долг (грабли впереди)

> [!note]
> - **Middleware deprecated в Next.js 16** — рекомендуется `proxy` файл. Работает, но при апгрейде убрать.
> - **Supabase JWT refresh оффлайн** — токен в localStorage ~1ч, без сети refresh упадёт. Продлить срок сессии при жалобах.
> - **`order` колонка int** — при drag-and-drop нужен fractional indexing (`order: 1.5`). Блокирует [[Features/dnd-week]].
